## Общие правила и спорные ответы

Все закрытые операции дополнительно возвращают 401 без действующей сессии, 403 при неверной роли/CSRF; принадлежность проверяется сервером. Чужой и неизвестный объект — 404. Валидация — 422, бизнес-конфликт — 409. POST возвращает Location при 201. Запросы staff ограничены собственной организацией/домом. Черновики доступны только авторизованному сотруднику нужной роли.

Публикация выражена подресурсом publications, а не глаголом publish. Изменение опубликованного документа и DELETE финансовой истории не предусмотрены. Ошибка: code, message, correlation_id без стека и чужих полей.

Повтор POST payment-attempts с тем же пользователем, ключом и телом возвращает ту же попытку: 200, либо 202 при pending. То же значение ключа с другим телом — 409. При тайм-ауте внешнего create сервер сохраняет pending и возвращает 202; новая попытка после подтверждённого отказа требует нового ключа и действующего quote. Успешная попытка блокирует оплату начисления навсегда в рамках MVP.

Webhook без подписи — 401, битый JSON — 400, несовпадающая сумма/валюта — 422 и диагностическое событие без изменения статуса; временная недоступность db — 503. Точный формат и криптографическая проверка определяются контрактом выбранного sandbox до ЛР 4. После commit дубль получает 204. Внешняя интеграция пока не проверена.

Служебный /internal не опубликован через nginx наружу. Scheduler в контейнерной схеме соответствует внешней системе эксплуатации на уровне контекста. Он запускает разовую сверку через API, worker независимо выполняет регулярную; оба используют блокировку строк, дубль не меняет итог.

История: limit 1–100, сортировка created_at DESC, id DESC; курсор содержит обе границы. Детали и все списки фильтруются по Membership. Возврат с платёжной формы ведёт только к чтению GET статуса.
