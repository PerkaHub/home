# Внесение изменений

GitHub Flow: одна короткая ветка на связную задачу, один запрос и ревью другим участником. Для трёх человек и общей поставки постоянные release/develop-ветки не нужны. До отправки выполнить проверки из README. Для кода используем `feat(scope): summary` и `refactor(scope): summary`, для документов и конвейера — `docs(scope): summary` и `ci(scope): summary`. Коммиты с первым сценарием и с рефакторингом оформляем отдельно.

В описании изменения назвать требования, затронутые решения и цену выбора, перечислить проверенные диаграммы и результат локальных проверок. Ревью: сначала согласованность требований и правил, затем безопасность платежа, затем оформление.

ADR принимает владелец проекта или уполномоченный им исполнитель; основание выбора указывается в записи. Замечания командного ревью фиксируются отдельно.
