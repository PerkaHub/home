# Ограничения физической модели

Все id технические UUID; время timestamptz в UTC. UK в ER — одиночный уникальный ключ. Составные ключи: house_id+account.number; account_id+charge.period для published; house_id+expense_report.period для published; user_id+payment_attempt.idempotency_key. Индекс payment_attempt(charge_id) уникален только для created/pending/succeeded. provider_id nullable до ответа; несколько NULL допустимы. FK charge.settled_attempt_id nullable, ссылается на payment_attempt.id и заполняется при подтверждении; обратная связь charge_id определяет принадлежность. Оба FK не каскадные; принадлежность проверяется транзакцией.

membership — явная связующая сущность пользователя и счёта; в MVP обе стороны ограничены уникальностью, при нескольких счетах в будущем ограничения пересматриваются. Черновик начисления может временно не иметь строк; диаграмма показывает обязательные строки опубликованного документа. expense_report допускает нулевой отчёт без категорий.

Пользователи-жильцы могут иметь NULL organisation_id; сотрудники обязаны иметь организацию. Общая таблица users — инфраструктурная модель Доступа, Organisation — справочник этого контекста. Session — техническая сущность ADR-0004, не доменный агрегат.

Деньги bigint в копейках, RUB; ставка integer в базисных пунктах (100 = 1%). Поля снимка предложения копируются в попытку, чтобы история не зависела от срока действия quote. settled_attempt_id — ссылка факта погашения, исходная сумма Charge не меняется.

Финансовые документы, попытки и события физически не удаляются; Account архивируется. Истёкшие сессии можно удалять; использованные приглашения сохраняются для связи Membership. FK RESTRICT, не каскадное удаление истории. Миграции и CHECK появятся в ЛР 4А. Этот документ служит основой для миграций.
