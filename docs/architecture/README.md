## Соглашение C4

Использован Mermaid flowchart с семантикой уровней C4: context показывает систему одним блоком, container раскрывает исполняемые процессы и хранилище. Лицо/система/контейнер, назначение и версии подписаны; стрелки односторонние с данными и протоколом. База цилиндром. Граница продукта одинакова на обоих уровнях: web, api, worker и db внутри; платёжный sandbox, планировщик и сборщик журналов учебного стенда снаружи. GitHub Actions проверяет репозиторий и не входит в контекстную диаграмму работающего продукта. Браузерный клиент показан web-контейнером как поставляемый nginx набор статических файлов.

## Результат пяти сверок

1. Контекст ↔ стороны: житель, представитель, бухгалтер присутствуют; внешние sandbox, планировщик и сборщик журналов обозначены на обоих уровнях. Планировщик вызывает систему, сборщик получает диагностические данные по NFR-05.
2. Контексты ↔ контейнеры: access/billing/transparency — модули api; worker использует тот же billing и его доменные правила.
3. Последовательность ↔ критерии: AC-01.4, AC-04.2, AC-05.2/3 отражены отказами; все участники соответствуют контейнерам и внешнему provider.
4. Контейнеры ↔ ADR, данные ↔ требования: технологии ADR-0002/3; таблицы доступа FR-01, начислений FR-02, расходов FR-03, предложений FR-04, попыток/событий FR-05/06; session — техническая необходимость ADR-0004. Сиротских сущностей не найдено.
5. API ↔ требования: FR-01–FR-06 имеют операции; endpoint не вводит новой функции MVP. Полная цепочка в [матрице](../traceability.md).

Результаты автоматических проверок приведены в [verification.md](../verification.md). Визуальное ревью диаграмм командой запланировано перед сдачей.

## Чего здесь нет и почему

Компонентный C4 — ЛР 3; миграции и OpenAPI — ЛР 4. Реальные деньги, микросервисы, кеш и брокер не входят в принятый объём. Версию API платёжного провайдера нужно определить после выбора тестового контура.

## Как обновлять

Сначала FR/AC, затем события и агрегаты, ADR, C4/ER/sequence, ресурсы API, матрица и журнал изменений. Все связанные файлы меняются вместе. После правки выполнить python scripts/check_docs.py и npm run diagrams; проверить SVG глазами и организовать ревью другим участником. ADR со статусом принято заменяют новой записью, сохраняя историю.
