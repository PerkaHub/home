# 0003. Развернуть модульный монолит с отдельным worker

- **Статус**: принято
- **Дата**: 2026-11-07
- **Участники проекта**: Белянский Глеб, Опекин Егор, Рогачев Егор
- **Основание принятия**: проектный выбор по поручению владельца проекта от 07.11.2026

## Контекст

Три контекста должны сохранять границы без сложности распределённых транзакций.

## Движущие факторы

C-01: три человека; NFR-06: чистый domain; NFR-02: атомарный учёт оплаты. Источники: [требования](../requirements.md), [агрегаты](../domain/aggregates.md).

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Модульный монолит | Одна БД и транзакция платежа | Совместное масштабирование модулей |
| Микросервисы | Независимые поставки и масштабирование | Сетевые контракты и распределённая согласованность |

## Решение

Модули access, billing, transparency в одном API. Четыре контейнера внутри системы: web, api, worker, db. Планировщик и сборщик журналов принадлежат учебному стенду и находятся вне границы продукта на обоих уровнях C4. Планировщик вызывает служебный endpoint api через внутренний HTTPS-шлюз стенда; worker независимо обрабатывает created и pending из db каждые 60 с по протоколу восстановления. Брокер не нужен. Для NFR-05 api и worker формируют обезличенные JSON-журналы с correlation_id: локально в stdout и дополнительно во внешний сборщик по HTTPS. Экспорт не участвует в финансовой транзакции; при недоступности сборщика локальные журналы сохраняются, внешняя доставка может задержаться или потеряться. Токены, приглашения и персональные данные не экспортируются. Это проектное решение для ЛР 4, доступность сервисов стенда и формат приёма журналов ещё нужно проверить. Compose — с ЛР 3. Проверка в ЛР 3Б: AST по modules/*/domain запрещает fastapi, sqlalchemy, infrastructure и чужой application; CI завершится ненулевым кодом при нарушении.

Определяющий довод — C-01 и NFR-02: общий commit проще распределённого протокола.

## Последствия

Положительные: Одна БД и транзакция платежа. Отрицательные: Один сбой API затрагивает три модуля; межагрегатная координация привязана к PostgreSQL. Что пересмотрит решение: Появление независимых команд и измеренной потребности масштабировать один контекст.
