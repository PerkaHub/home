# 0004. Использовать серверные сессии и Argon2id

- **Статус**: предложено
- **Дата**: 2026-11-07
- **Участники**: Белянский Глеб, Опекин Егор, Рогачев Егор; согласование запланировано

## Контекст

Нужно различать учебные роли и немедленно прекращать доступ.

## Движущие факторы

FR-01, NFR-04: серверная проверка прав; C-03: браузер. Источники: [требования](../requirements.md), [агрегаты](../domain/aggregates.md).

## Рассмотренные варианты

| Вариант | За | Против |
|---|---|---|
| Серверная сессия в PostgreSQL | Немедленный отзыв и простая модель браузера | Запрос к БД на проверку сессии |
| Короткий JWT | Проверяется без запроса к хранилищу | Отзыв до истечения требует дополнительного состояния |

## Решение

Учётные записи заранее созданы. Пароли только Argon2id-хеши с индивидуальной солью; параметры настроить нагрузочным замером в ЛР 4Б. Случайный session token хранится у клиента в Secure/HttpOnly/SameSite=Lax cookie; в БД только hash, срок 30 мин. неактивности и 8 ч. абсолютный. CSRF token и проверка Origin для изменений. Выход отзывает сессию. HTTPS на стенде. Права на каждый account_id/house_id проверяет сервер; неизвестный и чужой ресурс дают одинаковый 404.

Определяющий довод — NFR-04: отзыв доступа без ожидания истечения JWT.

## Последствия

Положительные: Немедленный отзыв и простая модель браузера. Отрицательные: Дополнительное чтение БД и уборка истёкших сессий. Что пересмотрит решение: Мобильные клиенты или федеративный вход.
