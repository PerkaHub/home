# Симуляционная встреча: проверка проектных решений

Дата: 07.11.2026. Формат — сценарное ревью с позициями аналитика, разработчика, тестировщика и эксплуатации. Основа для сравнения — требования ЛР 2 и актуальные проектные документы. Архитектурные решения ADR-0001–0005 приняты для текущей спецификации по поручению владельца проекта.

| Позиция | Проверяемый сценарий | Вывод и изменение |
|---|---|---|
| Аналитик | Все семь шагов жителя имеют требования | FR-01–FR-06 покрывают путь; границы MVP сохраняются |
| Разработчик | Сбой после commit до сети | Worker должен выбирать created, не только pending. Добавлены поручение, аренда, снимок запроса и AC-05.7 |
| Тестировщик | Webhook раньше create-ответа | Безусловное pending недопустимо; заменено условным переходом из created, AC-05.6 |
| Эксплуатация | Два worker и падение владельца аренды | Короткая аренда, SKIP LOCKED и lease_token; сеть вне транзакции |
| Эксплуатация | Срок гарантированной идемпотентности истёк | Запрет нового create, продолжение сверки и диагностический признак, AC-05.8 |
| Автор клиента | Формат ошибки 409 | RFC 9457: application/problem+json, type/title/status/detail/instance и расширения |
| Разработчик БД | Житель не сотрудник организации | Организация у пользователя необязательна; связь settles показана отдельно |

## Проектные выводы

Сохранены модульный монолит, серверные сессии, PostgreSQL и отсутствие кеша финансовых статусов. Изменены восстановление незавершённой отправки и порядок поздних ответов. Сборщик журналов и планировщик остаются внешними системами стенда на обоих уровнях C4.

## Контроль решений

Каждый участник выбирает цепочку FR → агрегат → ADR → ER/API, воспроизводит локальные проверки и оставляет замечания. Итоги и подтверждения добавляются к этому документу или в ревью изменений. Защита должна включать объяснение сбоя между commit и сетью и гонки webhook/create.
